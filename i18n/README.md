# i18n — переводы контента

Переводы документации в формате, который ожидает Docusaurus. Русский (`ru`) —
локаль по умолчанию и живёт в `docs/`; переводы лежат здесь.

## Структура

```text
i18n/<locale>/docusaurus-plugin-content-docs/current/
  └─ <те же пути и имена файлов, что и в docs/>
```

- Пути и имена файлов **должны совпадать** с `docs/`, чтобы маршруты мапились
  один-к-одному (`/docs/...` ↔ `/<locale>/docs/...`).
- Переводим только `title`/`sidebar_label` во фронтматтере; `id`/`slug`
  оставляем как в оригинале.
- Примеры кода и справочник API не переводим — только текст вокруг них.

## Что переведено (en)

`index`, `start`, `channels`, `guides/*`, `integration/*`, `faq`.
**Юридические документы (`legal/`) намеренно не переводятся** — для них
Docusaurus автоматически показывает русскую версию (fallback на локаль по
умолчанию), и она остаётся юридически обязывающей.

## Что нужно в репозитории движка (`talkyhub-docs-site`)

Этот репозиторий — только контент. Чтобы переводы заработали, в движке нужно:

1. В `docusaurus.config.ts` включить локали:
   ```ts
   i18n: { defaultLocale: 'ru', locales: ['ru', 'en'] }
   ```
2. Добавить переключатель локали в navbar (`type: 'localeDropdown'`).
3. На этапе сборки копировать `i18n/` из этого репозитория в корень сайта
   (рядом с `docs/`).
4. Строки интерфейса (navbar/footer) переводятся на стороне движка через
   `npm run write-translations --locale en` (файлы `code.json`), не здесь.

## Подписи разделов (en)

Подписи категорий сайдбара переводятся **не** через `_category_.json` в `i18n/`, а через
`docusaurus-plugin-content-docs/current.json` (ключ `sidebar.tutorialSidebar.category.<русская подпись>`).
Добавили или переименовали раздел в `docs/` — обновите этот файл, иначе на английском останется русская
подпись. Ключи можно сгенерировать в движке: `npx docusaurus write-translations --locale en`.

Плашки (admonitions) — только в синтаксисе `:::note[Заголовок]`: старый вид `:::note Заголовок` движок не
распознаёт и печатает как текст.
